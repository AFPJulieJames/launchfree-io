The single biggest event was **2026-09-14 itself**: 124 records pulled from a backlog-heavy Pending

On 2026-09-09, `docs/BUILD_SPEC.md` section 5 was rewritten to be **approve-by-default** with a
narrow, explicit reject list (dead/parked/empty links, fraud/ToS abuse, crypto tokens-as-product,
deceptive claims, minor safety, not-a-product). That rewrite is what made the 09-09 and 09-14
backlog-clearance passes possible — a 128-record pass on 09-09 alone cleared most of the old
"Pending Further Review-Email sent" backlog that the 08-29 handoff flagged as three weeks deep.

Case law that solidified this window (apply these without re-litigating):
- Same builder resubmitting the same product within minutes: keep the earliest record, delete the
  rest, never rebuild the dupes.
- Submission collides with an already-live listing under a different slug: delete the new
  submission, don't rebuild.
- Service/consulting businesses: approved case by case, no blanket ban (EinfachAI).
- If a comparable product is carried by Product Hunt or similar directories despite gray-area ToS
  concerns, approve it (reversed Akis and IPVIZO from reject to approve on this basis).
- Unaffiliated AI-model resellers using a trademarked model name in their product name: approved
  when the non-affiliation disclaimer is prominent (DeepSeek-V4.io, H3 Max Studio).
- Studio/portfolio pages are allowed as their own listing alongside individual product listings from
  the same builder.
- Genuine live waitlist/coming-soon pages: approved and tagged Stage = Coming Soon rather than held
  (established 09-10, shipped ZORO as the first case — see `claude/waitlist-policy-and-zoro-build-2026-09-10.md`).
- Stream-ripping tools (unauthorized extraction from Spotify/YouTube/Instagram/TikTok): reject as
  ToS abuse (spotmp3, Akis-the-second-one).
- Reused templated "shell" clusters (same product structure, swapped copy, near-identical) get held,
  not built, until it's clear each is a distinct real product.
- Em dashes discovered in a submitted *product name* get normalized to a colon before building (not
  reverted, not left as-is) — applied to 8 products total across two passes (Wednesday's audit + the
  09-14 build). Flag Julie if any should be reverted to the verbatim submitted name.

Two slugs needed a qualifier this window to avoid collision: `bot-company-os-maxwellai` and
`conversion-snapshot-24-auditforge`.

### Site bugs found and fixed

- **Ampersand over-encoding bug (found 09-04):** `docs/rebuild_listings.py`'s `esc()` function was
  re-escaping already-escaped values read back from prior page HTML, stacking up to 5 layers of
  `&amp;amp;` on 46 listing pages — corrupted outbound backlinks, broken gallery image URLs (404s),
  garbled titles on 7 pages. Root cause pinned to specific lines in `rebuild_listings.py`; a fix
  script (`docs/fix_amp_encoding.py`) plus a root-cause patch to `esc()` were both written and
  verified clean on a clone. **Confirm with Julie whether this was actually applied and committed**
  — the 09-04 audit found it, didn't push it.
- **`directory.html` stale meta description (found and fixed 09-08→09-09):** its SEO/AEO-visible
  meta description was frozen at a stale listing count while every other surface had the current
  number — a regenerator gap. Fixed.
- **Validator blind spot (found 09-09, partially fixed):** `validate_build.py` only scanned listing
  pages for em dashes, missing them in directory/category cards sourced straight from
  `listings.json`'s `name`/`tagline` fields. The `name`/`tagline` check was added; the same gap still
  exists for the `desc` field (browse.html only, low priority, still deferred as of 09-14).
- **Em dash in product *name* rendering as real SSR body copy (found 09-14):** `rebuild_listings.py`'s
  `fix_dashes()` normalizer runs on story/bio text but passes the `name` field through raw via
  `esc()`, so an em dash in a submitted name ships untouched into the H1, breadcrumb, Visit button,
  and directory/category cards. Working fix is the colon-normalization case law above (no slug
  rename); the underlying generator gap itself is still open.
- One leftover AI-chat preamble and raw markdown found live in a listing's description (czatuj24,
  09-09) — fixed.
- Recurring low-priority items flagged in every audit, still open: no duplicate-product guard in
  `validate_build.py` (relies on slug uniqueness only), `browse.html` still serves a JS shell instead
  of SSR, homepage `Organization.logo` uses a non-square image.
- **09-13: an Airtable status-reversion mystery** — 12 of 60 records pulled that day were carryovers
