**Version 1.0. Written 2026-08-16 from the live repo, not from memory.**
Every rule below was verified against the 235 pages currently in `AFPJulieJames/launchfree-io`.

same way, every single time.** If a step here conflicts with any older doc, this file wins.

House style: no em dashes in body copy, anywhere, ever. The one exception is the title separator
described in section 7, which is a structural character, not prose.

## 1. The one rule

**Every new listing page is produced by filling in `docs/LISTING_TEMPLATE_SSR.html`. Nothing else.**

Not by copying whichever page happens to be open. Not by hand. Not from `template.html`. Not from
a zip. One template, one process, one result.

The reason this matters: the repo used to hold two different page shapes, because pages were
generated by different methods at different times. Two shapes means two sets of bugs, two things to
fix whenever anything changes, and no way to tell "wrong" from "just older." All 235 pages were
rebuilt from this template on 2026-08-16, so there is now exactly one shape. Keep it that way.

**The page is server-rendered.** All real content lives in the static HTML. JavaScript only handles
interaction: tab switching, the Supabase upvote, copy link, copy badge. The test is simple: turn
JavaScript off, load the page, and you must still see the product name, the tagline, the
description and the builder story. If you see a blank page or the word "Loading", it is wrong and
it must not ship. This is not a preference. Fifty six pages shipped client-rendered and were
invisible to Google, GPTBot, ClaudeBot, PerplexityBot and CCBot until they were rebuilt on
2026-08-16.

| `Category` | yes | one of the list in section 3 | |

| `Builder Story` | yes | 1000 chars | The "Why I Built This" text |
| `Builder Name` | yes | none | |
| `Builder Email` | yes | none | Never published on the page |
| `Builder Bio` | yes | 400 chars | Sidebar text |

## 4. The slug rule

The slug is the filename, the vote key in Supabase, and the dofollow backlink. It is decided once
and never changed. Renaming a live slug breaks all three at the same time.

Derive it from the product name, deterministically:

1. Lowercase.
2. Strip accents (`á` becomes `a`, `é` becomes `e`).
3. Replace `&` with the word `and`.
4. Replace every run of non-alphanumeric characters with a single hyphen.
5. Trim hyphens from both ends and collapse doubles.

| Product name | Slug |
|---|---|
| VC Dekho | `vc-dekho` |
| Pocket Invoice | `pocket-invoice` |
| agentskills.codes | `agentskills-codes` |
| Filings.ae | `filings-ae` |
| Café Núñez | `cafe-nunez` |
| RouteSheet | `routesheet` |
| Nozzio | `nozzio` |

Note that the live listing for Hacé Cuentas is `haccuentas`, produced before this rule existed. It
stays as it is. Historical slugs are never corrected to match the rule, see below.

**Collision check before you build.** If the slug already exists in `listings.json` or in
`listings/`, and it is a different product, append a short stable qualifier such as `-app` or the
platform name. If it is the same product, it is already live: skip it, do not rebuild it.

**Historical slugs stay.** Roughly a quarter of the catalog uses an older concatenated style
(`blurbackground`, `videoupscaler`). Those URLs are permanent and indexed. Consistency starts with
new pages. We do not rewrite history and break links to make a list look tidy.

## 5. Review standard (what gets built at all)

Before anything is built, open every submitted URL live and judge it. Record one line per
submission: **Approve**, **Review**, or **Reject**, plus the reason.

**Approve** when the URL loads, the product is real and usable, and the submission describes what
is actually there.

**Reject** for any of:

- Dead link, parked domain, empty page, or a login wall with nothing behind it
- Fraud or terms-of-service violation: OTP or verification bypass, reselling other people's AI or
  software subscriptions, account trading
- Crypto tokens, coins, or investment schemes
- Deceptive claims, fake testimonials, invented metrics
- Anything unsafe involving minors
- Not a product: a blank template, a personal blog post, an affiliate landing page with no product

**Review** when it is fixable and worth an email: the URL is not live yet, the same builder
submitted the same product twice, a trademark problem, or the listing needs one clarification.
Send the review email and hold the submission. Do not build it.

Duplicate submissions of the same product collapse to one listing. One builder submitting several
genuinely different products is fine, and each is judged on its own.

**Only confirmed Approves get built.**

## 6. Copy rules

- **No em dashes in body copy.** Not in the description, the story, the bio, or the tagline. Rewrite
  with a comma, a colon, or two sentences.
- Never use "maker" or "co-maker." Approved words: **builder** (primary), **founder**, **co-builder**.
- The sidebar heading is always **Behind the Launch**.
- The share heading is always **Get Your Launch Seen**, with the standing copy already in the
  template.
- Light editing of builder text is expected: fix typos, break walls of text into paragraphs, cut a
  hard sell. Do not rewrite their voice and do not add claims they did not make.
- The description on the page is the full submitted description. The `desc` field in
  `listings.json` is a shortened version (section 9).
- Never publish `Builder Email`, `MRR`, or `How Did You Hear`.

## 7. Building the page

Copy `docs/LISTING_TEMPLATE_SSR.html` to `listings/<slug>.html` and replace every placeholder.

| Placeholder | Source | Rule |
|---|---|---|
| `{{NAME}}` | Product Name | As submitted |
| `{{SLUG}}` | derived | Section 4. Appears in canonical, OG url, share links, and the vote script |
| `{{TAGLINE}}` | Tagline | One line. No trailing period |
| `{{CATEGORY}}` | Category | Exact value from section 3 |
| `{{STAGE}}` | Launch Status | Section 3. Default `Live` |
| `{{PRICING}}` | Pricing | Delete the whole `tag-pricing` span if not supplied |
| `{{DATE_LONG}}` | build date | `August 16, 2026` format |
| `{{PRODUCT_URL}}` | URL | Full `https://` URL |
| `{{DESCRIPTION_HTML}}` | Description | Wrap each paragraph in `<p>...</p>` |
| `{{BUILDER_STORY}}` | Builder Story | Plain text inside the existing `<p>` |
| `{{BUILDER_NAME}}` | Builder Name | Also fills the JSON-LD `author` |
| `{{BUILDER_INITIAL}}` | derived | First letter of Builder Name, uppercase |
| `{{BUILDER_HANDLE}}` | Twitter | Leave the div empty if not supplied |
| `{{BUILDER_BIO}}` | Builder Bio | Plain text |
| `{{LOGO_BLOCK}}` | Logo URL | `<img src="URL" alt="NAME" />` if supplied, otherwise the uppercase first letter of the name as text |
| `{{OG_IMAGE_URL}}` | Logo URL | Falls back to `https://launchfree.io/og-image.png` |
| `{{NAME_URLENC}}` / `{{TAGLINE_URLENC}}` | derived | URL-encoded, for the X share link |
| `{{RELATED_CARDS}}` | derived | Three cards linking to other launches in the same category |
| `{{BUILDER_EXTRA_LINKS}}` | LinkedIn, Twitter | Extra `<a class="builder-link">` tags in the sidebar. Leave empty if neither was supplied |
| `{{GALLERY_IMAGES}}` | Screenshot 1/2/3 | One `<div class="gallery-img"><img src="URL" alt="NAME screenshot" /></div>` per screenshot. **If there are no screenshots, delete the whole Screenshots card**, which is marked with a comment in the template |

### The seven things that must be in the static HTML

Check these on every page before it ships. This is the SEO and AI-visibility contract.

1. `<title>` is `Name — Tagline | LaunchFree.io` with real values. Never "Loading".
2. `<meta name="description">` is `Tagline. Listed on The Runway at LaunchFree.io.`
3. `<link rel="canonical">` points at `https://launchfree.io/listings/<slug>.html`. **Never the
   homepage.**
4. Open Graph and Twitter tags with real title, description, url and image.
5. A real `<h1 class="listing-name">` with the product name, plus the tagline, category, the full
   description text and the builder story, all present as HTML.
6. Two JSON-LD blocks: `SoftwareApplication` (name, description, url, applicationCategory, author)
   and `BreadcrumbList` (Home, The Runway, this page).
7. The Supabase vote script, tagged `data-lf-vote-backend="1"`, with `SLUG` set to this page's slug,
   and a `<button class="upvote-btn">` on the page for it to bind to.

### Optional blocks

Delete, do not fake:

- No Logo URL: `{{LOGO_BLOCK}}` becomes the uppercase first letter, and `{{OG_IMAGE_URL}}` becomes
  the site default `https://launchfree.io/og-image.png`.
- No Pricing: delete the `tag-pricing` span.
- No Twitter: leave `builder-handle` empty.
- No LinkedIn or Twitter: leave `{{BUILDER_EXTRA_LINKS}}` empty.
- No Builder Story: delete the story tab button and the `panel-story` block together.
- No screenshots: delete the whole Screenshots card from the overview panel. The template marks it
  with a comment.
- Featured listing (a paid or editorial placement): add `tag-feat` to the category tag and set
  `featured: true` in `listings.json`. This is rare and it is a Julie decision, not a build step.

## 9. The six surfaces

A page file on its own is invisible. **Every build touches all six of these, in one commit.**

| # | File | What to do |
|---|---|---|
| 1 | `listings/<slug>.html` | The new page, built from the template |
| 2 | `listings.json` | Append one record per launch. Append, do not rewrite the file |
| 3 | `sitemap.xml` | One `<url>` block per new page, before `</urlset>` |
| 4 | `llms.txt` | One line at the top of "Recent launches", and bump the live count |
| 5 | `directory.html` | Regenerate from `listings.json`. Counts and ItemList JSON-LD refresh |
| 6 | `categories/<category>.html` | Add the new launch to its category page and update that page's count in the title, the H1 block and the ItemList JSON-LD |

`browse.html` needs no change. It fetches `listings.json` live on page load. `index.html` also
fetches `listings.json` live, but its hero stat span (`id="stat-count"`) is a static number that
crawlers and AI engines read without running the JS, so `regen_indexes.py` now stamps the live
catalog count into it on every build. `validate_build.py` errors if that number ever drifts from the
`listings.json` record count, so do not hand-edit it: run the generators.

Surface 6 is the one that used to get missed. The category pages are static HTML and they do not
read `listings.json`, so they only change when something regenerates them. On 2026-08-16 they were
56 launches behind. `docs/regen_indexes.py` now regenerates surfaces 5 and 6 together from
`listings.json`, so the reliable move is to run it rather than hand-edit either one.

### `listings.json` record format

Append exactly this shape, in the same field order:

```json
{
 "id": "<slug>",
 "name": "<Product Name>",
 "tagline": "<Tagline>",
 "desc": "<first ~150 chars of the description, cut at a word boundary, ending in the ellipsis character if truncated>",
 "emoji": "<first letter of name, uppercase>",
 "logo": "<Logo URL or empty string>",
 "cat": "<Category>",
 "url": "<Product URL>",
 "stage": "<Stage>",
 "votes": 0,
 "featured": false,
 "slug": "<slug>",
 "date": "YYYY-MM-DD",
 "mrr": ""
}
```

The `desc` rule above is a going-forward rule, not a description of the existing file. Today 114 of
235 records carry the full untruncated description and 53 are hard-cut at exactly 150 characters
mid-word with no ellipsis. Leave those alone. New records follow the rule.

Fixed rules: `id` always equals `slug`. `votes` is always `0`, because real counts live in
Supabase and the file value is ignored. `featured` is `false` unless this is a paid or editorial
feature. `mrr` stays empty, always: it is intake-only data and it does not get published.

### `sitemap.xml` block

```xml
<url><loc>https://launchfree.io/listings/<slug>.html</loc><lastmod>YYYY-MM-DD</lastmod><changefreq>weekly</changefreq><priority>0.6</priority></url>
```

### `llms.txt` line

```
- [Name](https://launchfree.io/listings/<slug>.html): <tagline> (<Category>).
```

Then update the sentence that reads "There are currently N live launches".

## 9b. The fast path: let the generators do it

Surfaces 1, 5 and 6 are mechanical. Two scripts do them correctly every time:

```
python3 docs/rebuild_listings.py --write   # re-renders every listing page from the template
python3 docs/regen_indexes.py --write      # rebuilds the category pages, directory.html, llms.txt
python3 docs/validate_build.py             # machine pre-flight, must report 0 errors
```

Both are idempotent: running them when nothing has changed writes nothing. Both read files only and
never touch git. The normal batch flow is: write the new page and append to `listings.json` and
`sitemap.xml` by hand, then run `regen_indexes.py --write` and `validate_build.py`.

## 10. Pre-flight checklist

Run every line. Fix anything that fails before committing.

**The page**

- [ ] File is at `listings/<slug>.html` and the slug follows section 4
- [ ] Title is `Name — Tagline | LaunchFree.io`, no "Loading" anywhere in the file
- [ ] Canonical is the page's own URL, not the homepage
- [ ] Real `<h1>`, real description text, real story text, all in the static HTML
- [ ] Both JSON-LD blocks present and valid JSON
- [ ] `data-lf-vote-backend` script present and its `SLUG` matches the filename exactly
- [ ] A `class="upvote-btn"` button exists
- [ ] Three related cards, all pointing at pages that exist
- [ ] No `{{PLACEHOLDER}}` left anywhere in the file
- [ ] No em dashes in the body copy

**The data**

- [ ] `listings.json` is valid JSON and has one new record per launch
- [ ] `id` equals `slug`, `votes` is 0, `mrr` is empty
- [ ] No duplicate slugs
- [ ] Every slug in `listings.json` has a matching file in `listings/`, and the reverse
- [ ] `sitemap.xml` has one new `<url>` per page and still ends with `</urlset>`
- [ ] `llms.txt` has one new line per page and the count matches the real total
- [ ] `directory.html` shows the new total
- [ ] Each new launch appears on its category page and that page's count is updated

**The commit**

- [ ] No stray folders in `listings/` (no `listings 2`, no nested `listings/`), no leftover zips
- [ ] The changed-files list is exactly what you expect and nothing else

A surprise in the diff is a signal to stop, not to push.

## 11. Commit and deploy

**Only GitHub Desktop touches git. The assistant never runs a git command against this repo,
including `git status`.** Two git processes on one repo leave a stale `.git/index.lock` that blocks
every future commit. The assistant reads and writes files, nothing more.

1. Open GitHub Desktop with `launchfree-io` as the current repository.
2. Check the Changes list against the pre-flight expectation.
3. Commit with a clear summary, for example `Add 9 new listings (8/16 batch)`.
4. **Fetch origin.** If newer commits exist on the remote, **Pull origin** first.
5. **Push origin.** GitHub Pages redeploys in roughly one to three minutes.

If a commit fails with "a lock file already exists": quit GitHub Desktop, run
`rm -f "/Users/jules/Documents/Claude/LaunchFree Hub/launchfree-io/.git/index.lock"` in Terminal,
reopen GitHub Desktop, and retry.

## 12. Post-deploy verification (definition of done)

On the live site, after Pages redeploys:

- [ ] `https://launchfree.io/listings/<slug>.html` loads and shows its content
- [ ] **View Source** on that page shows the title and description text in the raw HTML, not just
      after rendering. This is the check that catches a client-rendered regression
- [ ] The upvote button shows a number (0 is correct for a new launch) and it comes from Supabase
- [ ] The launch appears in the homepage or browse grid
- [ ] The launch appears on its category page and in `directory.html`
- [ ] `sitemap.xml` and `llms.txt` include the new slugs
- [ ] No stray path is live, for example a `listings/listings 2/...` URL returns 404

Nothing is done until these pass.

## 13. Anti-patterns (each of these caused real rework)

- **Building from `template.html`.** It fills the page from a `LISTING` object with `init()` at
  runtime. That produced 56 pages that crawlers saw as a blank "Loading" shell with a homepage
  canonical.
- **Copying whichever listing page is open** instead of the template. This is how two page shapes
  ended up in the repo.
- **Unzipping a delivered folder into the repo.** This created the duplicate `listings 2` folder.
  Pages are written straight into `listings/`, one file at a time.
- **Ad-hoc slugging.** Filenames that did not match the catalog.
- **Renaming a live slug.** Breaks the backlink, the shared URL, and the Supabase vote row at once.
- **Treating `listings.json` vote numbers as real.** Votes live in Supabase. File values are always 0.
- **Publishing a page without updating all six surfaces.** The page exists and nothing links to it.
- **The assistant running git.** Leaves a stale lock that blocks GitHub Desktop.

Review every URL live, approve only real working products, derive one kebab-case slug and never
change it, build the page by filling `docs/LISTING_TEMPLATE_SSR.html` so all the content is in the
