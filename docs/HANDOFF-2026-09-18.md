## Finding: iCloud sync was locking files mid-validation (not a content bug)

Re-ran the validator a bit later to sanity-check the warning count and it jumped from the
expected ~15 pre-existing warnings up to **1256 "could not read page (Resource deadlock
avoided)" warnings** — 82% of the site. Traced it: not a validator or content problem.
Confirmed the same error on a plain `head`/`cat` outside Python, on files of completely
normal size (~29KB, right for a listing page), and it didn't clear after waiting.

Root cause, confirmed with Julie directly in System Settings: **iCloud Drive's "Desktop &
Documents Folders" sync is on for this Mac, with "Optimize Mac Storage" also on.** This
repo lives at `Documents/Claude/LaunchFree Hub/launchfree-io`, so it's inside that sync
scope. When a big batch of file changes lands (today: 87 new + touched files across two
builds), iCloud grabs the whole folder to re-sync, and other programs trying to read those
files get locked out during that window. Not data loss, not corruption, just a temporary
read-lock while iCloud churns.

**This is a recurring risk, not a one-time glitch** — it'll happen again after any future
big build day, for as long as this folder is under active iCloud sync with storage
optimization on. Two ways to handle it, Julie's call:

1. Do nothing, just expect the validator (and possibly GitHub Desktop's diff view) to be
   briefly unreliable for a few minutes after a big build while iCloud catches up.
2. Turn off "Desktop & Documents Folders" sync for this Mac (System Settings → Apple ID →
   iCloud → Drive). This only affects the Desktop/Documents folders specifically — Photos,
   Notes, Messages, etc. are unaffected. **Confirmed safe to do for this project**: the
   repo's real backup is GitHub (full history, independent of iCloud), not iCloud sync,
   and today's build is already pushed. The only thing to watch is that this toggle
   applies to the whole Documents folder, not just this repo, so anything else living in
   Documents that isn't backed up elsewhere (another git repo, Time Machine, etc.) would
   lose its automatic iCloud copy too.

No action taken either way — flagging it here so it's not forgotten, and so a future
Claude session doesn't mistake a big fresh warning count for a real regression.
