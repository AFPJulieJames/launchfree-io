## Backend — Supabase (`launchfree-votes` project, live in production, nothing in this repo)

No files in this repo changed for this part. It lives entirely in Postgres on
Supabase, applied directly through the SQL Editor.

- **New table `public.vote_events`**: one row per vote, with a salted, hashed
  IP (`ip_hash`, never the raw IP) and a timestamp. Has RLS enabled, no anon
  policies, no direct client access.
- **`public.increment_vote(slug)`** (same signature and return type as
  before, still called from every listing page's upvote button): now logs to
  `vote_events` first. A duplicate vote from the same visitor for the same
  listing in the same calendar week is silently ignored (`ON CONFLICT DO
  NOTHING`) and the existing total is returned. A real vote still increments
  `public.launch_votes.votes`, the same all-time counter the site has always
  used for "Most votes" sort and the trending score. That counter is
  untouched and still works exactly as before.
- **New view `public.weekly_leaderboard`** (`slug`, `votes_this_week`),
  granted `SELECT` to `anon`. This is what the homepage's Top 20 pulls from.
  It counts votes in a **rolling trailing 7-day window**
  (`created_at >= now() - interval '7 days'`), not a fixed Monday-to-Monday
  bucket. A listing submitted on any day of the week gets a full 7 days
  counted from when its votes land, nothing gets cut short by a calendar
  boundary. There is no weekly "reset moment" anymore: whatever the view
  returns right now is always a fair trailing-week count. Pick the
  newsletter's top 20 by checking it whenever you're ready to write, not by
  waiting for a particular day.

## What did NOT change — submission workflow

**The six-surface build process is untouched.** A new listing still touches
exactly the same six things it always has: the page, `listings.json`,
`sitemap.xml`, `llms.txt`, `directory.html`, and its category page.
`index.html` was never one of the six surfaces and still isn't. It fetches
`listings.json` live and re-renders, so a correctly-built new listing shows
up on the homepage automatically:

- It appears in **Just Landed** the moment it's live, for as long as it's
  one of the 8 newest by submission date.
- It becomes eligible for **This week's top 20** as soon as it gets its
  first vote, counted on the same rolling 7-day basis as everything else.
  No separate step, no manual placement.

Nothing about where or how you send submissions in changes. Build it the
same way BUILD_SPEC.md always described, and it lands everywhere it needs to.

## Where do all live listings live now?

**`directory.html`**, unchanged by tonight's work. It was already the
full, server-rendered catalog of every live listing (regenerated by
`docs/regen_indexes.py`) and already the page crawlers and AI engines are
pointed at. The homepage's "Browse all [count] launches by category" button
links there. The homepage never duplicated that job and still doesn't, it's
just no longer trying to *also* be an endless scroll of everything.
