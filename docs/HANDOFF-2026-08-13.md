## Voting system fixed (the big one)

Problem: votes only showed on Julie's own launches. Cause: the homepage and browse grid read the
static `votes` numbers baked into `listings.json`, where only the six seed sites had hardcoded
values. The live Supabase counts only drove the individual listing pages, and almost no real votes
existed yet.

Fix (in `index.html` and `browse.html`):
- On load, the grid now batch-reads all live counts from Supabase and displays them.
- The grid's upvote button now writes to Supabase (`increment_vote`), guarded per slug, matching the
  listing pages.
- Sorting by votes uses live counts.
- Zeroed the six hardcoded seed votes so nothing has a head start. New records are always `votes: 0`.

Verified live: `foodsavr` shows its real 3 votes on the grid (was 0), the seed sites show 0, and new
listings show 0 until clicked. The whole site now reflects real engagement.

## Standards and docs created

- **`docs/RUNBOOK.md`** (in the repo): the full step-by-step SOP for building new listings, with the
  slug rule, the four surfaces to update, the pre-flight checklist, the GitHub Desktop flow, the
  post-deploy verification, and the anti-patterns that caused today's rework.
- **`LaunchFree_Project_Instructions.md`** (for project knowledge): standing context, the live-review
  standard, the slug rule, the no-git rule, and the deploy flow. Add or replace this in the LaunchFree
  project knowledge so it loads every session.
- **Slug standard settled.** Going forward every slug is kebab-case (lowercase, accents stripped,
  `&` to `and`, runs of punctuation to a single hyphen). Decided once, never renamed. Existing
  concatenated slugs stay as they are, renaming would break their backlinks and vote rows. This is
  why some old pages have hyphens and some do not: there was never one rule before, now there is.
