That is invisible to GPTBot, ClaudeBot, PerplexityBot, CCBot and friends, and it risks Google not indexing those listings on their own URLs.

## How listing pages MUST be written (so this does not recur)

**A listing page is server-rendered. The real content lives in the static HTML, not in JavaScript.** JavaScript is only for interaction (tab switching, the Supabase upvote, copy-link, copy-badge). If you can turn JavaScript off and the page is blank, it is wrong.

Every listing page must contain, in the static HTML before any script runs:

1. `<title>` = `Name — Tagline | LaunchFree.io` (real values, never "Loading...").
2. `<meta name="description">` with a real sentence (tagline plus "Listed on The Runway at LaunchFree.io.").
3. `<link rel="canonical">` pointing at the page's OWN URL (`https://launchfree.io/listings/<slug>.html`), never the homepage.
4. Open Graph and Twitter tags with real title, description, url, and image.
5. A real `<h1>` with the product name, plus the tagline, category, and the full description text and builder story rendered as HTML.
6. Two JSON-LD blocks: `SoftwareApplication` (name, description, url, category, author) and `BreadcrumbList`.
7. The Supabase vote script (`data-lf-vote-backend`) with `SLUG` set to the page's slug, wired to a `.upvote-btn`.

The current 234 live pages are the reference. Copy their structure. Do not reintroduce the old "fill everything with `init()` from a `const LISTING` object" pattern; that is exactly what caused the blank pages. `template.html` in the repo is the legacy JS-render skeleton and carries a warning at the top; build from the server-rendered pattern instead.

## Exactly what gets committed to git when new pages are added

When you approve N new launches, the commit contains these files and nothing else:

1. **`listings/<slug>.html`** — one server-rendered page per launch, built to the rules above. One kebab-case slug per launch, decided once, never renamed.
2. **`listings.json`** — append one record per launch (append, do not rewrite):
   `{ "id": slug, "name", "tagline", "desc", "emoji", "logo": "", "cat": category, "url", "stage", "votes": 0, "featured": false, "slug": slug, "date": "YYYY-MM-DD", "mrr": "" }`
   `id` and `slug` are the same value. `votes` is always 0.
3. **`sitemap.xml`** — insert one `<url>` block per new page before `</urlset>` (loc, lastmod, changefreq weekly, priority 0.6).
4. **`llms.txt`** — insert one line per new page at the top of "Recent launches"
   (`- [Name](https://launchfree.io/listings/<slug>.html): <tagline> (<Category>).`) and bump the "currently N live launches" count.
5. **`directory.html`** — regenerate from `listings.json` so the new launches appear (grouped by category, with the ItemList JSON-LD and category counts refreshed). This is now part of every build.

`index.html` and `browse.html` need no change: they fetch `listings.json` live and update themselves.

Pre-flight before committing: every new page has a real title/description/canonical/H1/JSON-LD (no "Loading", no homepage canonical), valid JSON in `listings.json`, no duplicate slugs, sitemap still ends with `</urlset>`, llms count updated, directory shows the new total, and the changed-files list is exactly the five items above. Then commit, fetch, pull, push in GitHub Desktop. The assistant never runs git.
